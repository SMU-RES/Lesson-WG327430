# 汽车上位机

直接打开本目录的汽车上位机.csproj。整个应用只有这一个工程，界面、通信、数据库和三维代码都位于源码目录中。

开发环境需安装支持 C# 12 的 .NET SDK（8.0 或更新版本）及 Windows 桌面开发组件。项目仍以 .NET 6 Windows 为目标，发布为 win-x86 自包含程序，依赖 S7netplus 0.20.0 与 Microsoft.Data.Sqlite 8.0.20。

从源码/Main.cs 开始阅读：

1. Main 先取得单实例互斥量，再创建数据库、显示登录窗口并进入主窗体。固定课程账号和密码都是 shmtu；登录仅确定记录身份，PLC 控制仍须申请远程会话。
2. 界面/操作窗口.cs 负责控件事件、操作许可和后台记录队列。按钮调用通信服务，不直接写 PLC。按住车窗按钮才保持请求，松开、失焦或切换页面都撤销保持。
3. 通信/通信服务.cs 是唯一 S7 交换循环。界面线程在锁内更新命令意图，通信线程复制完整命令，再完成连接、握手、顺序锁写入、读取反馈和异常清理。
4. 通信/命令镜像.cs、接口协议.cs、状态快照.cs 说明 DB100/DB101 字节布局、票号语义、数据质量和有符号角度。模式票或一次票的变化表示新请求，最终执行状态以 PLC 反馈为准。
5. 界面/集成视图.cs 把同一个已验证状态交给二维、三维和原生数值栏；记录接收时刻是为了避免 UI 排队把旧反馈延长成新反馈。
6. 数据/本地数据库.cs 使用参数化 SQL 与事务保存实验备注，测量缺失写 NULL。快照发布.cs 用有界队列异步写诊断文件，磁盘操作不参与运动控制。
7. 三维/LowPolyCar.cs 生成固定车身网格；CarGeometry.cs 定义雨刷和车窗的显示坐标；SnapshotReader.cs 只接收程序内状态。OpenGl.cs 管理 WGL 生命周期、网格缓存和限帧，QualityPolicy.cs 在低帧率时降低显示负载。

汽车控制页顶部的原生工具栏提供连接、软件停止和复位。界面/工具栏.cs 将每项映射到现有按钮，保持相同启用状态并调用原按钮事件，没有单独的 PLC 写入逻辑。

线程与状态边界：

- UI 线程操作控件；S7 循环独占连接；SQLite 与诊断快照在后台写盘。
- 本机请求、PLC 会话许可、轴就绪和动作完成是不同状态。界面禁用用于提示，PLC 继续执行自己的完整仲裁。
- UI 存活超过 400 ms 未更新会撤销会话和保持；反馈超过 600 ms 未更新会清除显示。通信恢复后先对齐票号，不重放旧动作。
- 防夹按钮生成 300 ms 输入脉冲，并设 3 s 冷却；PLC 决定锁存、停车和反向过程。
- 三维在已收到的两帧间插值，只改善显示连续性，不生成电机位置或反馈质量。

在 PowerShell 中构建：

    .\构建.ps1

发布到相邻的 C#可运行文件目录：

    .\构建.ps1 -Publish

也可指定独立的发布目录：

    .\构建.ps1 -Publish -OutputDirectory 'D:\汽车上位机发布'

构建暂存位于本目录上两级的 build/汽车上位机 中，不会写入交付源码。运行时完整保留发布目录，在其中启动汽车上位机.exe。数据库和诊断快照默认位于当前用户的 LocalApplicationData/汽车综合实践，可通过 --data-dir=绝对目录 指定数据位置。
